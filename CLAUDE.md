## Project

Personal portfolio site for Vlad Horobets (Senior Front-End Developer). Single-page site composed of stacked sections (Hero / About / Skills / Experience).

## Stack

- **Nuxt 4** (`^4.3.1`) with the new `app/` source directory layout
- **Vue 3** `<script setup lang="ts">` SFCs
- **Tailwind CSS** via `@nuxtjs/tailwindcss`
- **@nuxt/fonts** for self-hosted Inter (weights 400/500/600/700)
- **lucide-vue-next** for icons
- **sass-embedded** — `.vue` files may use `<style lang="scss">`

## Commands

```bash
npm run dev        # dev server on http://localhost:3000
npm run build      # production build
npm run generate   # static site generation
npm run preview    # preview built output
```

There is **no test runner, linter, or formatter configured** — do not invent `npm test` / `npm run lint`. If verification is needed, run `npm run build` to surface type/build errors.

## Architecture

### Nuxt 4 `app/` layout
All source lives under [app/](app/). Standard Nuxt auto-imports apply:
- Components in [app/components/](app/components/) are auto-imported globally — **do not** add `import Foo from '~/components/Foo.vue'`. Nested components flatten by directory: [app/components/Skills/Skills.vue](app/components/Skills/Skills.vue) is referenced as `<Skills />`, [app/components/Experience/ExperienceItem.vue](app/components/Experience/ExperienceItem.vue) as `<ExperienceItem />`.
- Composables in [app/composables/](app/composables/) are auto-imported (e.g. `useScrollReveal`).
- Vue/Nuxt APIs (`ref`, `useRoute`, `useTemplateRef`, `useHead`, `useSeoMeta`, lifecycle hooks) are auto-imported — no manual import.
- Static data and types **are not** auto-imported — import explicitly from `~/data/...` or `~/types/...`.

### Page composition
[app/pages/index.vue](app/pages/index.vue) is the only route; [app/app.vue](app/app.vue) just renders `<NuxtPage />`. SEO/meta lives on the index page via `useSeoMeta` / `useHead`.

### Scroll reveal pattern
Sections animate in on scroll using a small reusable system:
1. [app/composables/useScrollReveal.ts](app/composables/useScrollReveal.ts) — composable that takes a template ref, attaches an `IntersectionObserver`, and toggles `.scroll-reveal--visible`.
2. [app/assets/css/main.css](app/assets/css/main.css) — defines `.scroll-reveal` (initial hidden state), `.scroll-reveal--visible` (revealed), and `.scroll-reveal-child` (children that animate together with their parent).
3. Sections in [app/pages/index.vue](app/pages/index.vue) opt in by passing a `ref="..."` and calling `useScrollReveal(theRef)`. Child elements add `class="scroll-reveal-child"` to participate (see [Skills.vue](app/components/Skills/Skills.vue) and [Experience.vue](app/components/Experience/Experience.vue)).

When adding a new animated section, follow this same three-step pattern rather than re-rolling animation logic.

### Data / types separation
- Static page content lives in [app/data/](app/data/) as typed `export const` arrays (e.g. [skillGroups.ts](app/data/skillGroups.ts), [experiences.ts](app/data/experiences.ts), [socials.ts](app/data/socials.ts)).
- Types live in [app/types/](app/types/), grouped into per-domain folders (`skills/`, `experience/`, etc.), with a `T` prefix convention: `TSkillItem`, `TSkillGroup`, `TExperienceProps`, `TSocial`, `THeaderItem`. Match this when adding new types.
- Components consume data via the typed data modules — keep content out of components.

### Tailwind theme
[tailwind.config.js](tailwind.config.js) defines a custom dark palette (`primary`, `secondary`, `accent`, `card`, `border`, `foreground`, `muted-foreground`, etc.) and a `font-custom` family (Inter). Prefer these semantic tokens over raw Tailwind colors.

Common composed utility classes (`.section-title`, `.section-subtitle`) are defined under `@layer components` in [app/assets/css/main.css](app/assets/css/main.css) — reuse them for new section headings instead of duplicating the utility soup.

### TypeScript
The root [tsconfig.json](tsconfig.json) only references the generated configs under `.nuxt/` (Nuxt 4 split tsconfig). Do not edit `.nuxt/*` directly — it's regenerated by `nuxt prepare` (run via `postinstall`).
